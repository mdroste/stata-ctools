# Compatibility

Each ctools command aims to work like the command it replaces, and for everyday use the syntax is the same. Not every option is implemented, some commands add options of their own, and the estimators can differ from the originals in solver details. This page covers those differences. For full syntax, see `help <command>` in Stata.

Each ctools command is pinned to one version of the command it replaces, and the differences below are relative to that version. [Attribution](ATTRIBUTION.md) lists the pinned versions.

In the Weights column, `aw`, `fw`, `pw`, and `iw` are Stata weight types. A dash means the command doesn't accept weights.

## cpsmatch matching

With `ties` and k > 1 neighbors, matching with replacement, `cpsmatch` matches every donor that is at most as far away as the k-th nearest one, each once. `psmatch2` matches the donors tied with the nearest one and then the k − 1 next positions around the nearest. A donor tied with the nearest is therefore matched twice and weighs twice, and donors tied at the k-th distance are left out. `cpsmatch` corrects both on purpose, so on a score with ties its `_weight`, `_nn`, matched outcomes, effects and standard errors differ from `psmatch2`'s. The first k entries of a row's matches (`_n1` to `_nk`) are the ones `psmatch2` lists without `ties`.

The rule covers `neighbor(k)` and the same-arm matches of `ai(k)` (`_self_<outcome>`, and through them the `ai()` standard errors). With one neighbor (`neighbor(1)`, `ai(1)`) or a score without ties, both commands match the same donors. Without replacement `cpsmatch` follows `psmatch2`, including for `ai()`: a row's first same-arm match is taken without replacement and its other `ai()` matches are the rows around that one, used or not.

With `ai()`, an arm with a single observation on support has no same-arm match. Matching on the score, `psmatch2` then takes the observation that follows it in its sort order as the match, if that one has a score within the caliper: the first observation of the other arm, one with another treatment code, one off support, or one outside the sample. `cpsmatch` does the same, so the two agree, but those standard errors have no statistical meaning. Where `psmatch2` stops with a Mata error, r(3301), `cpsmatch` stops with r(2001) and a message: when no observation follows (a single treated observation that is last in that order), and with `mahalanobis()` and `w()`.

Mahalanobis matching also corrects loss of information after translating covariates: it uses centered rank screening and distances formed from coordinate differences. Inputs whose names collide with generated outputs are rejected before they can be deleted.

## cpsmatch standard errors

`cpsmatch` reports the same ATT standard error as `psmatch2` does by default:

```
SE = sqrt(s1²/n1 + s0² · Σ w0² / n1²)
```

Here `n1` is the number of matched treated observations, `s1²` and `s0²` are the unweighted outcome variances among the matched treated observations and among the controls on support, and `w0` are the controls' matching weights. Squaring the weights accounts for controls used more than once and for fractional matches. Like `psmatch2`'s default, this ignores the uncertainty from estimating the propensity score. With `ate`, the ATU and ATE have standard errors of the same kind (the formulas are in `help cpsmatch`).

The Unmatched row also follows `psmatch2`: its standard error comes from an OLS regression of the outcome on treatment.

With `ai(#)`, `cpsmatch` reports the Abadie–Imbens (2006) standard errors of the population effects, and the `samplevar` and `altvariance` (Abadie et al. 2004) variants, as `psmatch2` does. When `cpsmatch` estimates the score itself, they are also corrected for that estimation (Abadie and Imbens 2016) under the conditions `psmatch2` applies, and `debug` returns the parts of the correction.

These standard errors are the ones of `psmatch2` 4.1.0, which differ from 4.0.12 and from ctools 1.3.0 and earlier:

- Without `ai()`, `s0²` covers every control on support. Before, it covered only the controls used as a match, so the ATT standard error changes whenever a control goes unused. ATU and ATE standard errors used to be missing.
- `ai()` reports the population variance by default and `samplevar` requests the sample variance. Before, the sample variance was the default and `population` requested the other; `population` is no longer an option. `ai(#)` now equals the old `ai(#) population`, plus the correction where it applies, and `ai(#) samplevar` equals the old `ai(#)`.
- New stored results: `r(ai)`, `r(ai_vartype)`, `r(ai_pscorr)`, `r(ai_pscorr_method)` and the matrix `r(table)`.

Matches, weights, generated variables and point estimates are the same in both versions, except that an ATT-only call with the correction leaves `_nn` missing and `_pdif` filled for the controls.

## String variables

Most commands accept numeric variables and fixed-length strings up to `str2045`. Support for `strL` varies: `cencode`, `cdecode`, `csplit`, `cmerge`, `creshape` and `csort` call Stata commands when needed; the other commands read strL text of any length and binary values (strL `by()` keys of `crangejoin` and strL keys of `cjoinby` are refused, as in `rangejoin` and `joinby`). Import and export limits depend on the file format. See the command help for format-specific limits.

## When a command fails

`cmerge`, `cjoinby`, `crangejoin`, `cwinsor`, `crangestat`, `creghdfe`, and `cimport` undo their changes if they fail or you press Break, without writing a copy of the dataset to disk. Two options change this:

- `snapshot` runs `preserve` on the whole dataset first. It's slower on large data, since Stata writes the snapshot to disk once it exceeds `c(max_preservemem)`.
- `fast` keeps no copy at all. It saves time and memory, but a failure or Break can leave the data partly changed.

On Stata 14 and 15, which don't have frames, `cimport`, `cjoinby`, `crangejoin`, and some `cmerge` merges use `preserve` instead.

`creshape` checks a request before it changes anything, and then holds the original observations in the plugin until the new form is complete: if Stata cannot build it, the data are put back exactly, without a copy on disk. Break waits until the command finishes. It has no `snapshot` or `fast` option.

`csort` and `cbsample` keep no copy of the dataset, like `sort` and `bsample`. Break waits until they finish. `csort` puts the original rows back if a sorted value cannot be written, except in streaming mode. An error while `cbsample` expands the sample leaves it partly drawn. Run `preserve` first if you can't reload the data.

Like Stata's own commands, `cimport` clears the data before reading SAS, SPSS, XPORT, dBase, and shapefiles, so a failed import of those formats leaves an empty dataset unless you specify `snapshot`.

If any command says the data in memory may be incomplete or partly modified, reload your data before you continue.

New variables created by `creghdfe` (residuals, group IDs, saved fixed effects), `crangestat`, and `cencode` must have names that aren't already in use. As in `reghdfe`, every `creghdfe` run drops `__hdfe*`, `residuals` without a name replaces `_reghdfe_resid`, and `absorb(..., replace)` replaces `newvar=` targets.

## Estimation errors

- **One cluster.** A clustered covariance matrix isn't defined with a single cluster. `creghdfe` and `civreghdfe` exit with error 498. `cppmlhdfe` exits with error 459, since it needs at least two clusters in every cluster dimension. `cqreg` posts a zero covariance with `e(rank)` 0 and displays no standard errors, as `qreg` does.
- **No convergence.** Exhausting the fixed-effect solver's iterations in `creghdfe`, `civreghdfe`, or `cppmlhdfe`, or the PPML iterations in `cppmlhdfe`, gives error 430 instead of estimates (`creghdfe ..., abort(0)` keeps the projection with `e(converged)` 0). Numerical breakdown in the shared CG projection gives r(498); `abort(0)` cannot override it.

## Performance

Speedups depend on the number of observations and variables, variable types, options, hardware, and thread count. In some cases ctools is slower than the command it replaces. See the [benchmarks](performance/README.md) for measured results.
