P1 refactoring fixes — September 29, 2026

This implements the six P1 items in [the organization audit](REFACTORING_AUDIT_2026-09-28.md). The working tree already contained extensive changes, and additional transport/I/O work arrived during this task. Those changes were preserved. The current launcher is `stata` in an interactive login zsh; older reports describing completed `oldstata` runs remain historical records.

1. **Explicit command lifecycle and cleanup ownership.** [ctools_commands.def](../src/ctools_commands.def) is the dispatcher’s source of wire names, state owners, handlers, and cleanup hooks. The runtime tracks the active owner and successful phase. It rejects an execute/write/metadata call without its required preceding phase; a new scan, a command switch, or any error discards the previous session. CSV import and generic format I/O have separate owners. PPML’s cleanup hook now releases its actual persistent state. Merge cleanup also releases partially constructed caches and resets an interrupted operation’s in-use marker after workers have joined. Version queries remain non-destructive. The obsolete previous-command bookkeeping and duplicate dispatch chains were removed.

2. **Checked shared parsing.** [ctools_parse.h](../src/ctools_parse.h) defines a bounded token cursor and distinct absent, invalid, and successful results. Named options match complete tokens, quoted values may contain whitespace, duplicate valued options are rejected, and oversized values are rejected instead of truncated. Signed integers and unsigned seed halves are range checked. Floating-point options reject nonfinite values and trailing junk. Sampling/bootstrap and range-statistics parsers now share these helpers; positional counts are checked before allocation. Encoding and destring callers respect the new statuses. Merge/import reject oversized command strings before copying into their existing protocol buffers.

3. **One validation inventory.** [suites.json](../validation/suites.json) records suite paths, runner types, categories, fixtures, dependencies, and completion markers. [suite_registry.py](../validation/suite_registry.py) validates file coverage and generates the Stata master list. Both the local native gate and Linux CI consume this inventory. The Stata gate now checks `memory_safety` completion and includes command-optimization checks, boundary-contract checks, four I/O suites, the quantile smoke checks, merge edge cases, real-SPI strL tests, and the data-I/O smoke test. Benchmarks and large-data experiments are explicitly categorized rather than automatically included. Independent extra suites continue after failures, and any failure still fails the overall gate.

4. **One Stata launch boundary.** [stata_runner.py](../validation/stata_runner.py) constructs the interactive-login-zsh `stata` invocation, quotes driver paths, assigns a fresh completion nonce, checks the saved Stata return code, requires `exit, clear`, and cleans up its temporary executable driver. The existing audit and I/O runners use it; benchmark preparation tools use its command constructor. Excel and delimited fixtures receive their directories as arguments rather than using a developer’s home directory. Tests cover spaces in paths, missing/stale completion records, error return codes, and driver cleanup.

5. **Explicit internal-to-Stata status conversion.** [ctools_types.h](../src/ctools_types.h) provides a common boundary converter: allocation → 920, invalid input → 198, transport read/write → 459, unsupported type → 109, cancellation → 1, singularity → 506, and nonconvergence → 430. Command adapters use it for shared load/sort/store errors instead of misreporting them as memory exhaustion or returning internal integers directly. Status-returning transport callbacks preserve cancellation before categorizing read/write failures. Shared Cholesky/inversion routines distinguish invalid input, allocation failure, and singularity; PPML now checks previously ignored inversion failures. Existing native SPI return codes remain native codes and are not passed through the internal converter.

6. **Explicit column storage ownership.** [stata_variable](../src/ctools_types.h) records whether its buffer is aligned, normally allocated, or borrowed, and whether string contents are owned or borrowed. [stata_variable_free](../src/ctools_types.c) implements the idempotent destructor. Merge marks its borrowed string contents and normally allocated pointer vectors, then uses the shared dataset destructor on all output-cleanup paths. Owners remain alive through the parallel store. Partially allocated datasets release their permutation even when column allocation failed. Empty string columns now use aligned buffers too, preserving the Windows allocator/deallocator pairing. Physical buffer-swapping permutations reject non-aligned views; order-only sorting and sorted stores remain available without mutating those buffers. Native tests model separate Windows aligned/ordinary deallocators and verify partial allocation, repeated destruction, and surviving borrowed strings.

The newly registered quantile smoke suite contained an obsolete success assertion for residual-density estimation with zero sparsity. That behavior is already rejected by the existing estimator. The suite now requires the specific `r(498)` error and retains its coefficient/convergence assertions using kernel density on the same tied-response data. Numerical tolerances were not changed.
